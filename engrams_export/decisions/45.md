description: "Decision #15 established CWD-based resolution for git reads (safe — read-only). The policy engine added implicit side effects via write_through() (called on every pattern log/delete) and staleness() (called by doctor). Both originally fell back to db::workspace_root() (CWD walk) when workspace_root_from_db returned None. This is unsafe for writes: a --db path outside <root>/engrams/context.db layout (tests, explicit --db) causes the fallback to find the CWD's workspace and overwrite its .omp/rules/ manifest with unrelated patterns. Observed: cargo test from repo root triggered s3 test's write_through to corrupt the real dogfood manifest with test fixtures. Fix: write_through/staleness use ONLY workspace_root_from_db(db_path); no-op if None. check.rs keeps the CWD fallback (read-only file collection, always invoked with known workspace context). Invariant: implicit side effects must never cross workspace boundaries."
